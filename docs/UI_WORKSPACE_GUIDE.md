# Pilot 对话与经验审核界面

本次只修改前端布局、展示和导航状态，不更改后端接口与业务状态流转。

## 页面组织

- 对话：全局侧栏 + 对话工作区。会话参数放进顶部设置；技术 ID 可查看和复制，接口路径放进调试说明。
- 执行过程：独立于回答显示。进入回答流时自动折叠，最终回答仍逐块渲染；错误堆栈与工具 JSON 按需展开。
- 本次问题：对话顶部按需展开，纠正状态、拆分、合并和调整事件归属仍可使用。
- 经验审核：默认阅读，点击编辑后显示原有字段表单。桌面聊天与审核并排，小屏聊天使用覆盖式抽屉。
- 知识库：左侧筛选和经验列表，右侧详情。参考文档上传与检索保留在折叠区域。

`experienceDrawer` 是同一个 DOM 组件：聊天挂载到 `chatReviewMount`，知识库挂载到 `knowledgeDetailMount`。两个入口共用 `knowledge-manager.js` 的加载、版本、编辑、校验、保存、发布、拒绝、归档和来源查看。

## 状态边界

`workspace.js` 只负责浏览器视图导航与轻量会话索引；Run 身份、事件去重、续接和取消仍由 `agent-chat.js` / `agent-session.js` 管理。

点击新会话只清空视图与审核状态，不关闭旧排障任务，也不调用创建或结束会话接口。首条消息发送时生成本地会话 ID，并通过原聊天接口初始化服务端会话。用户配置保留，空会话不写入历史索引。

切换期间保留原会话消息 DOM；原事件只更新对应的消息。加载历史用视图版本和会话 ID 检查返回值，审核用请求版本检查。未保存审核阻止切换并提供保存、放弃、继续编辑；失败时保留表单。历史中的活动 Run 通过 GET events 续接，不重复 POST 问题。

已有运行时在一个浏览器页面中只维护一个活动执行，本次沿用该限制：运行期间可以切换查看会话，但新的发送等待当前执行结束。审批等待期间先处理审批，再切换会话。

后端没有全账号会话列表接口。历史入口显示本浏览器按账号保存的最多 60 个会话索引，并提供按会话 ID 加载；完整消息和 Run 始终从现有服务端接口读取。

数据模型没有单独的“排查过程”字段，因此阅读区将 `root_cause` 呈现为“排查与根因分析”，不增加或编造业务字段。发布与验证状态保持独立。

归档经验的详情底部提供“恢复发布”。它复用经验更新接口的 `action=restore`，只恢复原 `published_version` 的检索资格，不修改内容、证据或验证状态；最新待审核修订保持待审核。后端检查归属、Revision、归档状态与原版本的 approved 状态，上次归档原因保留。

## 验证

```powershell
node --test web/app.test.mjs web/agent-session.test.mjs
& .\artifacts\startup\embedding-venv\Scripts\python.exe scripts/workspace_ui_smoke.py
& .\artifacts\startup\embedding-venv\Scripts\python.exe scripts/workspace_isolation_smoke.py
```

浏览器脚本使用此前隔离测试账号的真实经验和 Run，修改该测试账号下的修订，不使用伪造知识记录。网络失败测试只注入请求失败；异步隔离测试暂停真实接口响应和 SSE 回放，再检查切换后旧响应不会覆盖新视图。

已验证：桌面/移动布局、懒创建、历史恢复、执行过程折叠、对话侧边审核、共用审核、未保存切换提示、失败保留编辑、真实草稿保存/发布/拒绝，以及延迟历史/审核响应和流订阅隔离。现有 26 个前端测试通过，相关 JS 语法检查通过。

另外通过运行中的服务与配置的 DeepSeek Flash 完成一次真实流式对话（观察到多个回答增量）和一次非流式对话，均正常返回，没有页面脚本错误。截图和结果在忽略目录 `artifacts/workspace-ui`。
