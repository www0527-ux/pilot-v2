# 会话工作快照与事务提交

当前设计保留两张表：`conversation_histories` 保存用户原始问题与最终回答，供界面回看和知识整理；`session_contexts` 保存供下一轮模型继续工作的消息快照。快照可以包含用户/助手消息、工具调用及结果、已有摘要；临时 System Message 和工具定义每轮重新组装。

## 正常请求

1. `FullPilotAgent.Generate/Stream` 获得会话门闩。
2. `SessionContextManager.Load` 按账号、会话读取 `MessagesJSON`，恢复模型工作消息；不存在则从空上下文开始。此处不查询原始历史或 Redis。
3. Graph 加入系统提示、静态背景和当前问题，ADK 按需压缩并执行。
4. 最终回答完成后，`contextRun.save` 过滤临时 System Message，保留工作消息并追加最终回答。
5. `CommitTurn` 在一个短 MySQL 事务中保存工作快照和两条原始问答，然后释放会话门闩。原始问题使用用户输入，保留“继续”等原文，不保存内部改写指令。
6. 控制器更新缓存、Run 等记录，不再重复写主 Agent 的原始问答。历史多 Agent/测试适配器仍可使用控制器的历史写入路径，不属于当前主 Agent 的上下文来源。

模型和工具调用不在数据库事务内。两张表在成功提交时一起可见，任一写入失败全部回滚。流式文本可以早于事务提交到达页面；保存失败会以错误结束执行，保留本次 Run 已接收到的回答，下一轮继续使用上次成功提交的快照，不自动合并失败轮次的历史，也不自动重跑模型。

## 工作快照字段

| 字段 | 用途 |
| --- | --- |
| UserID / SessionID | 账号与会话范围，联合主键 |
| MessagesJSON | 完整模型工作消息快照，允许包含摘要 |
| Revision | 每次成功更新递增，阻止旧请求覆盖；冲突时原始历史写入也回滚 |
| LastRunID | 识别最近一次提交的重试，不参与上下文加载去重 |
| ContextVersion | 标记旧数据是否已完成启动迁移 |
| UpdatedAt | 上次成功保存时间 |

相同 Run、相同快照及原始问答重试提交时不重复写历史；更新的 Run 已提交后，旧版本请求会被拒绝。清空会话在事务中删除历史与 Run，并保留更高 Revision 的空快照，旧请求无法复活已清空内容。

## 从旧版本升级

升级前先停止旧服务及其在途任务，避免混用两种写入协议。`OpenDB` 自动迁移表结构后，在接受请求前执行 `migrateSessionContexts`：

- 仅对 `ContextVersion=0` 的旧快照使用一次旧游标和覆盖集合补齐历史，保留已有摘要和工具消息，再标记为新版本。
- 只有历史、没有快照的旧会话，在启动时导入一次；只能恢复原始问答，不能恢复历史表未保存的工具消息。
- 已迁移的快照不会在后续启动时重新拼接历史，空快照也不会被历史覆盖。
- 旧 `history_cursor`、`covered_runs_json` 数据库列暂时保留；新结构与正常加载不使用它们。迁移失败会阻止启动并回滚数据迁移。

该迁移不支持旧新实例同时运行，也不替代快照损坏后的专门恢复流程。
